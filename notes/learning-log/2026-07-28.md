## 🔀 React Flow → [full note](../react-flow.md)

**The mental model:** React Flow is a **controlled component**. You own two arrays — `nodes` and `edges` — in your app state; React Flow renders them and reports interactions (moved a node, drew an edge) back as change events you apply. Same "you hold the state, the library renders it" contract as a controlled `<input>`, scaled to a graph canvas.

What actually stuck:

- **It handles the fiddly canvas parts** — pan/zoom math, drag, connection handles, selection, viewport coordinates — so you build the *domain* (a workflow builder, pipeline editor, agent graph), not a canvas engine.
- **Four primitives cover most of it:** **nodes** (`{id, position, data, type}` — `data` is yours), **edges** (source→target), **handles** (the connection points on a node), and the **viewport** (the zoom/pan transform).
- **Nodes and edges are just React components** — register via `nodeTypes`/`edgeTypes`, put anything (forms, charts, buttons) inside, and declare connection points with `<Handle>`. That's the whole customization story.
- **State: go controlled for real apps.** `useNodesState`/`useEdgesState` are fine for demos, but lift nodes/edges into your own store — React Flow uses **Zustand** internally, and that's where undo/redo, persistence, and business logic belong.
- **No auto-layout** — you position nodes yourself, or integrate **Dagre/ELK** (hierarchical) or **d3-hierarchy** (trees). *This* is where real graph algorithms (topological sort, layered-DAG layout) show up.
- **The #1 performance bug:** defining `nodeTypes`/`edgeTypes` inline re-mounts every node each render. Define them module-level or `useMemo`, and `React.memo` custom nodes. It even prints a console warning.
- **Two setup gotchas that eat hours:** import the stylesheet (`@xyflow/react/dist/style.css`) and give the container an explicit height, or nothing renders.

> One-liner to remember: *own the nodes/edges state (controlled), nodes are just React components, define nodeTypes outside render, and reach for Dagre/ELK when you need auto-layout.*

## 🔗 Connections I noticed

- **A node editor is literally a graph.** Nodes + edges = the adjacency model from my DSA note, made visible and editable. Auto-layout is topological sort + layered-DAG placement — graph *algorithms* rendered on a canvas. The "big theory" and this "frontend library" are the same data structure at different altitudes, *again*.
- **Controlled vs. uncontrolled is the same fork as API design.** "Who owns the source of truth" — you (controlled, production) or the library (uncontrolled, demos) — is the exact distinction from the API note, now at the component level.
- **The perf lesson is the DSA lesson.** Rendering N nodes is fine algorithmically; it's the **constants** (needless re-mounts/re-renders) that kill you. Stable identities (module-level `nodeTypes`, stable `id`s, memoized `data`) are the fix — the React echo of "stable keys, no churn."
- **Knip walks a module graph; React Flow draws one.** Same node/edge model — one analyzes it invisibly, the other lets a user edit it.
