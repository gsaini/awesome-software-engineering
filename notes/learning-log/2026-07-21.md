## 🧪 Testing Strategy → [full note](../testing-strategy.md)

**The core reframe:** testing isn't about proving correctness (impossible) — it's about **buying confidence to change code**, delivered *fast enough that people actually run the tests*. Every decision trades against those two axes: confidence and speed.

What actually stuck:

- **The pyramid encodes a trade-off:** push most tests down (unit — fast, cheap, many); keep E2E rare (slow, brittle, high-confidence-per-test). The **ice-cream cone** (mostly slow E2E/manual) is the anti-pattern; the **Testing Trophy** (Kent C. Dodds) argues for more *integration* tests in modern app code. No universal ratio — push to the **lowest level that still gives real confidence**.
- **Test behavior, not implementation.** Assert observable outcomes, never private internals or "was this method called." Behavior tests survive refactors; implementation tests break on every one — which trains people to delete tests.
- **Test doubles have a precise taxonomy** (dummy/stub/spy/mock/fake) and it matters: **mocks verify you *called* things a certain way, not that the result is correct.** Over-mocked tests pass while the real integration is broken. Prefer **fakes over mocks**; mock only at real boundaries (I/O, time, randomness).
- **FIRST** (Fast, Independent, Repeatable, Self-validating, Timely) + **AAA** (Arrange-Act-Assert). "Independent / no shared state" is literally the concurrency lesson applied to the test suite.
- **Coverage ≠ confidence.** Line/branch coverage measures *what ran*, not *what was verified* — a test can execute a function and assert nothing. **Mutation testing** (Stryker/PIT) is the honest measure: inject faults, see if tests catch them. Coverage is a **floor to find gaps**, never a **KPI target** (Goodhart's law breeds assertion-free tests).
- **Flaky tests are corrosive out of proportion to their count** — a suite people don't trust is a suite people ignore. Causes: async/timing, shared state, non-determinism, external deps. **Quarantine immediately, fix or delete fast.**

> One-liner to remember: *test behavior not implementation, prefer fakes over mocks, and treat coverage as a floor to find gaps — never a target to hit.*

## 🔗 Connections I noticed

- **"Coverage ≠ assertions" is now a three-note through-line.** CRAP score (coverage as a weak input), agent evaluators (eval "coverage theater"), and now testing (mutation testing exists *because* coverage lies). Same truth from three angles — I think this is the single most reinforced idea in my whole library.
- **Evals are tests for non-deterministic systems.** The agent-evaluator note's "deterministic gates first, LLM-judge for the fuzzy stuff" is exactly the pyramid: cheap/fast/certain checks at the base, expensive/slow/probabilistic ones on top.
- **"Write the test first" = "negotiate the contract first" = contract-first API design.** TDD, loop engineering, and API design all say: agree on the observable criteria *before* building. One discipline, three domains.
- **Independent tests = no shared mutable state = stateless fleet.** The "remove shared state to remove a bug class" instinct shows up in concurrency, load balancing, *and* test isolation.
- **Contract testing (Pact) answers the API-versioning problem** from the API-design note — verify provider/consumer still agree without booting both.
