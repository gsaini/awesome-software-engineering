## 🏗️ Infrastructure as Code (Terraform) → [full note](../infrastructure-as-code-terraform.md)

**The core reframe:** ClickOps makes infra a snowflake nobody can reproduce or review. IaC makes it a **declarative artifact in git** — you describe the desired end state, the tool converges reality to it. The unit shifts from "do these console steps" to "declare the end state; let it converge."

What actually stuck:

- **Declarative + idempotent.** You describe *what*, not *how*; `apply` when reality already matches is a **no-op**. Re-applying converges instead of duplicating — idempotency again, now for infra.
- **`plan` is the killer feature** — a dry-run diff (`+ create / ~ update / - destroy`) you review *before* applying. The big gotcha: some changes **force replacement**, so always check for a `- destroy` on a database before hitting apply. The plan is a **constraint gate**: never apply one you haven't read.
- **State is where all the power and pain live.** `terraform.tfstate` maps config → real resources; it's the source of truth for *what Terraform manages*. Rules: **remote backend + locking** (a concurrent-apply race corrupts it), **never hand-edit** (use `state` subcommands / `import`), **it contains secrets** (encrypt, restrict), and **split it** to bound blast radius.
- **Drift** = reality diverged from code (usually a manual console change). `plan` detects it, `apply` reconciles. The rule that prevents it: **no ClickOps on managed resources** — a manual "quick fix" is a future outage when the next apply reverts it.
- **Modules + same-module-different-vars** across dev/stage/prod is what *guarantees* environments match. Divergence = a symptom of not sharing the module.
- **GitOps + policy-as-code** — infra via PR: CI runs `plan`, human reviews, merge applies; OPA/Sentinel/tfsec **reject** non-compliant plans before apply.
- **Terraform vs OpenTofu** — HashiCorp relicensed Terraform to BUSL (2023); the community forked **OpenTofu** (Linux Foundation, MPL, drop-in). Know both.

> One-liner to remember: *declare desired state, always read the plan before apply, guard the state file (remote + locked + encrypted), and never ClickOps a managed resource.*

## 🔗 Connections I noticed

- **IaC is constraint-driven development for infrastructure.** The config is the spec; `plan` is the diff-gate; **policy-as-code (OPA/Sentinel)** is the *executable constraint / fitness function* — the exact idea as [dependency-cruiser](../dependency-cruiser.md) for code architecture. Same shift-left instinct as tests and commit linting.
- **Idempotency, ~Nth sighting** — `apply`-until-converged is the same "safe to repeat" principle as at-least-once consumers, retries, and durable-execution activities. Reliability keeps returning to *make repetition harmless*.
- **Terraform builds a resource DAG** — dependency graph → provision in order, parallel where possible. The graph structure, again (build systems, git, dependency-cruiser, now infra).
- **State-file locking is a concurrency race** — a shared mutable file two applies fight over; remote backend + lock is the mutex. The [concurrency](../concurrency-parallelism.md) note, at the ops layer.
- **This completes a three-day arc:** replicate data (multi-region) → split data (sharding) → **provision all of it reproducibly (IaC)**. The DR story from the multi-region note *depends* on rebuild-from-code.
