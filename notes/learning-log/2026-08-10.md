## 🌿 Git Internals & Workflows → [full note](../git-internals.md)

**The core reframe:** git is not a diff tool that stores changes between versions. It's a **content-addressable filesystem** that stores **complete snapshots**, each addressed by the hash of its content — and branches/tags/HEAD are just **movable pointers** into a graph of those snapshots.

What actually stuck:

- **Four object types, that's the whole store:** **blob** (file contents), **tree** (a directory), **commit** (a snapshot = tree + parent(s) + metadata), **tag**. A commit points to a tree and to its parents; follow parents back and you have the whole history as a **DAG**.
- **The address IS the hash of the content.** So identical content is stored once (dedup), integrity is built in (a changed byte changes the hash), and history is **tamper-evident** (a commit's hash depends on its parent, so rewriting an old commit changes every hash after it). This is *literally* pnpm's store and every content-addressed cache — hashing, again.
- **A branch is a 41-byte file** containing one commit hash. That's why branching is instant, and why `reset`/`merge`/`rebase` all reduce to "which commit does this pointer now point at?" **HEAD** points at a branch (or, detached, straight at a commit).
- **Merge vs. rebase:** merge makes a 2-parent commit (truthful, can tangle); rebase **replays** commits as new hashes (linear, clean, but rewrites history). **Golden rule: rebase local/private, merge public — never rewrite shared history.**
- **reset vs. revert:** `revert` makes a new undo-commit (safe on `main`); `reset` moves the branch pointer (`--hard` can lose uncommitted work). *Revert public, reset local.*
- **The reflog is the safety net:** git almost never truly deletes commits — every HEAD move is logged, so "lost" commits after a bad rebase/hard-reset are recoverable for ~90 days. Orphaned ≠ gone, just unreferenced.

> One-liner to remember: *git is a key-value store where key = hash(content); commits are snapshots in a DAG, branches are movable pointers — rebase local, merge public, and the reflog remembers everything.*

## 🔗 Connections I noticed

- **Content-addressing, fourth sighting — and now the tool under my hands.** DSA note (hashing) → pnpm store → MCP-adjacent caches → **git**. "Hash the content, use it as the key" is one of the most reused ideas in all of software, and git is the one I'd been using blind.
- **The commit DAG + tamper-evident hash chain is a blockchain before blockchains** — each block (commit) references the previous by hash, so the chain is integrity-checked end to end. Same structure as the replicated/append-only **log** that keeps showing up (WAL → Kafka → Raft → durable execution → now git history).
- **Yesterday's commitlint clicks into place:** conventional commit messages are metadata *on the commit objects* this note describes; curating them with interactive rebase is just rewriting local commit objects before they go public.
- **"History is forever + content-addressed" = the committed-secret danger** from my security note: you can't just delete a secret in a later commit, because the old blob is still reachable by hash. The internals explain the security rule.
