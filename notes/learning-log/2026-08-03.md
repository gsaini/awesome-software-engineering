## 🔌 Model Context Protocol → [full note](../model-context-protocol.md)

**The core idea:** MCP is an open standard — the "USB-C for AI" — that standardizes how AI apps connect to external tools, data, and systems. It turns the **M×N integration problem** (M apps × N tools = M×N bespoke connectors) into **M+N**: write one MCP server, every MCP host can use it.

What actually stuck:

- **Three roles:** a **Host** (the AI app) contains **Clients**, each with a **dedicated 1:1 connection** to one **Server**. Messages are **JSON-RPC 2.0**. The 1:1 rule is deliberate isolation — a bad server can't reach into others (least-privilege/blast-radius, again).
- **Three server primitives, split by who controls them:** **Tools** (model-controlled — the LLM decides to call, JSON-Schema input), **Resources** (app-controlled readable context by URI), **Prompts** (user-controlled templates). That control split — model/app/user = three trust levels — is the elegant part.
- **Client-side features invert the flow:** **Sampling** (server borrows the host's LLM), **Roots** (fs sandbox boundaries), **Elicitation** (server asks the user for structured input mid-task).
- **Transports:** **stdio** (local subprocess) and **Streamable HTTP** (remote, single endpoint + optional SSE).
- **The 2026-07-28 spec makes the protocol STATELESS** — it drops the `initialize` handshake and `Mcp-Session-Id`, so any server instance can serve any request. Plus cacheable list results (`ttlMs`/`cacheScope`, modeled on HTTP `Cache-Control`), W3C Trace Context in `_meta` for OpenTelemetry tracing, OAuth hardening, and an extensions framework.
- **A tool result is untrusted input** — a prompt-injection vector. Require human approval for consequential actions; treat every server as untrusted; scope OAuth tokens tightly.

> One-liner to remember: *MCP is the standardized tool/context layer under the agent loop — write one server, plug in any model; and always treat a tool result as untrusted input.*

## 🔗 Connections I noticed — my whole library, in one spec

This was wild: the *new* MCP spec is a checklist of things I already studied.

- **Stateless core = my load-balancing note.** Dropping session state so any instance serves any request is exactly the "stateless fleet → horizontal scale" lesson. A cutting-edge AI protocol reached for a decades-old distributed-systems move.
- **`ttlMs`/`cacheScope` = my caching note, verbatim.** A TTL as an explicit staleness bound, modeled on HTTP `Cache-Control`. They literally cited Cache-Control.
- **W3C Trace Context in `_meta` = my observability note.** Trace-ID-everywhere, now standardized across agent tool calls for OpenTelemetry.
- **Extensions framework = my serialization/schema-evolution note.** Evolve the protocol without breaking clients — backward compatibility as a first-class feature.
- **OAuth 2.1 hardening + least privilege = my S2S-auth and security notes.**
- **"Point the agent at another MCP server" = event-driven decoupling** — add a capability with no change to the agent, like adding a consumer with no change to the producer.
- **It sits right under loop engineering** — MCP is *how* the loop's "act" (tools) and "gather" (resources) actually happen, and its structured tool calls are exactly what an agent evaluator inspects.

The meta-lesson: **a genuinely new technology isn't new fundamentals — it's the same fundamentals, recomposed.** Studying the boring foundations for a month made a brand-new spec read like a summary of my own notes.
