## 🤝 Distributed Consensus → [full note](../distributed-consensus.md)

**The core problem:** get N unreliable machines to **agree on a single value and never un-agree**, even though any node can crash at any instant and messages get lost. It's how you get [linearizability](../consistency-models-cap.md) out of unreliable parts.

What actually stuck:

- **Safety vs. liveness is the whole lens.** Safety = "never decide two different values"; liveness = "eventually decide." You can *always* keep safety; it's liveness that networks and impossibility results threaten. **Mantra: never trade safety for liveness** — a wedged-but-correct cluster recovers; a split-brained one corrupts data forever.
- **FLP (1985):** in a *fully async* network you can't guarantee termination with even one crash — because you can't tell a crashed node from a slow one. Real systems dodge it with **partial synchrony** (timeouts) + **randomization** (Raft's election jitter — that word *again*). They stay safe always, live once the network settles.
- **Everything reduces to a replicated log.** If every replica applies the **same commands in the same order**, they converge — so consensus just needs to agree on **an ordered log**. That's the Replicated State Machine model, and it's literally the message-queue log with agreement bolted on.
- **Paxos** decides one value via overlapping majority quorums (Prepare/Promise → Accept/Accepted); **Multi-Paxos** elects a stable leader to stream entries. Famously correct, famously unreadable — which is *why Raft exists*.
- **Raft = the same power, decomposed** into three human-sized parts: leader election (terms + randomized timeouts), log replication (leader-only writes, commit on majority), and safety (a candidate needs an up-to-date log to win, so committed entries are never lost). Entries flow **leader → followers only** — that one-directionality is what makes it tractable.
- **Odd clusters, always.** Majority = ⌊N/2⌋+1; 3→4 or 5→6 adds a node but *not* fault tolerance. 5 tolerates 2 failures — the sweet spot. **2-node "HA" tolerates zero.** Split brain is prevented because only the majority side can elect a leader; the minority steps down (CAP's CP choice, live).

> One-liner to remember: *consensus = agree on an ordered log via majority quorums; keep safety always, get liveness when the network behaves, and always run an odd number of nodes.*

## 🔗 Connections I noticed

- **The overlapping-majority trick is `W+R>N` again.** Paxos quorums, Raft commits, and Dynamo-style quorum reads all rest on the same fact: two majorities always share a node, which carries the agreed value forward. Third context for the same math.
- **Consensus is the *implementation* of yesterday's CP corner.** CAP said "under a partition, CP systems refuse writes on the minority side." Today I saw the mechanism: the minority can't reach a majority quorum, so it *can't* elect a leader or commit. The theory and the machinery finally connect.
- **The replicated log is THE recurring abstraction.** DB write-ahead log → Kafka's event log → Raft's replicated log. Ordered + immutable + replayable keeps showing up as the universal backbone — 'The Log' paper was right.
- **"Deterministic commands" is the test-determinism lesson.** RSM convergence breaks if applied commands use wall-clock/random/map-order — the exact non-determinism that makes [tests flaky](../testing-strategy.md). Same rule, different stakes.
- **Jitter: fourth appearance** — cache stampede, retry storms, queue retries, now Raft election timeouts. Randomize to break symmetry / de-synchronize. It might be the most universally reusable trick I've collected.
